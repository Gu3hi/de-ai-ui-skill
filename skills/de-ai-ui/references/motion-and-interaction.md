# 动效与交互 / Motion & interaction

主要来源：@ZaynHao（动效基线）、@Kubai087（级联菜单 / 拖拽 / 按钮）、@dingyi（下拉箭头）、@Xian0063 转述的 Emil Kowalski 细节。要点转述；各原帖的长 Prompt 请到原帖复制（见 `sources.md`），本篇只留可检查的数值与行为结论。

## 1. 动效基线

- 能少则少。必须加时：**ease-out、约 250ms** 作为基础设定。[@ZaynHao]
- 滚动动效不要多，过渡要收敛，不要生硬地堆。[@dingyi]
- 进场用 ease-out 而不是 ease-in；菜单从触发点「长出来」，缩放从接近 1 的值开始（约 0.96），不要从 0 弹；按钮按下有轻微缩放（约 0.97）；通知类提示叠放，不要把内容挤走；长文本截断、大数字缩写，不要撑破卡片。[@Xian0063 转述 Emil Kowalski Skills]

## 2. 下拉 / 级联菜单

- **下拉按钮的小箭头要专门修**（@dingyi 清单第 19 条）：不用默认箭头充数；尺寸与字号匹配、光学居中、左右间距呼应、展开有状态变化。检查点见 `slop-checklist.md`。
- **级联菜单加安全三角区** [@Kubai087]：指针从父级斜向移往子菜单时，会擦过中间行；以指针上一位置为顶点、向子菜单近侧两角连成三角形，指针在三角内时不切换当前行。
- 配套延时（原帖数值）：悬停约 220ms 才打开子菜单；离开约 360ms 才关闭；指针在安全区内停住超过约 1.2s 后再切换到新行。拖拽经过文件夹行时打开延时更长（约 420ms）。
- 实现注意（原帖要点转述）：行高亮由组件状态驱动而不是纯 CSS `:hover`，否则安全区内被擦过的行仍会亮；延时值集中成命名常量；安全区几何做成可单测的纯函数。

## 3. 拖拽排序 [@Kubai087]

- 光标反馈：可拖元素悬停为手型、抓取中为抓手。
- 被拖元素要「抬起」跟随指针，不遮住落点；原位置收拢。
- 落点用一条细插入线提示（约正文色 15% 透明度），出现时从中间展开，移动时平滑跟随。
- 两侧元素按与插入线的距离让位：位移按 `A × 0.7^n` 衰减、启动延迟按 `24ms × n` 递增（n 为相隔层数，紧邻为 0；A 约 10px，卡片约 8px），效果像推挤的涟漪。
- 取消（Esc / 拖出）要能回弹复位；用 transform 实现，不触发 layout；键盘也要可排序；reduced-motion 时只保留插入线。

## 4. 按钮手感 [@Kubai087]

拟物按钮的要点不是「像真按键」的外观，而是**状态完整 + 材质分层一致**：

- 先复用项目已有 Button 体系（变体、token、API、无障碍），不另造组件。
- 变体由强到弱分档（如 primary → text），各变体共用同一套材质层结构（面、边、顶部高光、底部暗部、双层投影），只换数值，并抽成 token。
- 按下态要完整：位移 1px、明暗翻转、外投影收紧、高光转内阴影；静止与按下态的内阴影层数保持一致，动画才不会跳。
- 尺寸随字号等比缩放：所有长度写成字号单位的倍数，而不是写死像素。
- 时序参考（原帖）：transform 约 120ms、阴影约 140ms、颜色约 160ms。

## 5. 减少「需要判断」的交互 [@ZaynHao]

- 尽量减少页面中需要用户停下来判断才能继续的交互。
- 必须出现时，放在用户本来就打算做选择的位置；同时重排信息优先级，让默认路径尽量不需要判断。
